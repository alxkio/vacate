# Database-owned test organization

Product lead direction, 2026-11-14, under VAC-42: persist test-company facts in SQL and remove runtime fixture fallbacks. Accepted ADR-0003/0004 remain the architecture/persistence authority. This is fictional development data, not a statutory entitlement calculation or production identity rollout.

SQL owns the organization/test marker, employees, employment dates, reporting relationships, prior service, structure/settings, explicit development login allowlist, entitlement inputs and dated requests. Balances remain derived from leave rows; do not persist replacement Used/Pending/Available totals. PriorServiceYears is experience before the current employer, with explicit zero distinguished from unknown.

The member workspace endpoint supplies current structure/directory and privacy-safe away dates. The frontend preserves public GUIDs, consumes saved own leave separately and never generates colleague absences. Names, lead labels, account hints and groups come from stored records. Provisional catalogue descriptions/rules are code/reference material, not stored employee facts. Browser display preferences retain their accepted per-browser behavior.

`DevelopmentLogins` is an explicit operator-owned allowlist. IsDemo is an additional boundary, not a login grant by itself. No passwords are persisted. SQL mode never instantiates InMemoryDatabase or loads the embedded fictional roster. The SQL seeder and its empty-database bootstrap command are removed. Deterministic InMemory setup and the roster live under `api/testing/`, compiled only into automated tests or an explicit non-publishable test build. Default API/Infrastructure assemblies contain neither the fixture loader nor its JSON resource. Frontend company/leave fixtures live only under `frontend/testing/`.

## Dev database execution · 2026-11-15

After explicit product-lead authorization, the operator connected with its existing Entra identity to the named dev SQL database. `DatabaseDevelopmentLogins` and the runtime read grant had already been applied by [deployment run 43648689837](https://github.com/alxkio/vacate/actions/runs/43648689837); the empty allowlist correctly blocked application publication.

Two rollback-only previews exposed script assumptions before any commit: identity columns use `Latin1_General_100_BIN2` rather than the database default collation, and the existing marked company uses UTC rather than Europe/Athens. The script now matches those stored values and preserves the company's timezone. The corrected preview passed all guards, then the complete batch was committed atomically with explicit apply enabled.

Independent SQL readback confirmed the test marker, twelve employment profiles (eleven reporting managers, one owner/root), fourteen explicit aliases (twelve advertised and two legacy), two ten-working-day summer blocks per person across 2025/2026, and recorded consumption leaving 5–9 days against each configured custom allowance. This is a provisional remainder: the saved policy minima are null, so actual API allocation/available remain unknown under the existing contract. All twelve pre-existing employee-created leave rows were compared by public GUID, dates, status, quantity and request lifecycle values against the pre-operation snapshot and were unchanged. A rollback-only replay reported zero added days for all twenty-four member/year combinations. No entitlement policy, company setting, employee-created request or other tenant was deliberately rewritten.

This verifies the named data operation and its replay on Azure SQL. It does not replace the broader SQL provider/concurrency/grant regression suite, whose previously skipped checks remain separately tracked.
